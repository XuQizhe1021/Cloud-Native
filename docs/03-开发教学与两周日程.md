## 1.1 老师给的文件怎么用

1. `E:\trae\云原生\ubuntukelong`
   - 这是 **已经做过基础配置的 Ubuntu 虚拟机文件夹**

直接结论：

### Windows 本机做
1. Java 后端编码

3. Git 提交
4. Markdown 文档编写
5. YAML、Bash 脚本编写

1. Kubernetes 集群搭建
2. Jenkins 部署
3. Prometheus 部署

### 最推荐的工作方式
**Windows 负责开发，VMware 虚拟机负责部署。**

你不要一开始就在虚拟机里写代码，那样会非常慢，也容易乱。

## 5. 第一周 Day2：启动三台虚拟机并配置网络

老师的 PDF 已经明确说了：**除了 IP 相关配置，其他基础环境基本都已做好。**

## 5.1 先确定 VMware 的 NAT 网段

### 操作步骤
1. 在 VMware 顶部菜单点击 `Edit`
2. 点击 `Virtual Network Editor`
3. 找到 `VMnet8`
4. 看它的 `Subnet IP`

例如你可能看到：
`192.168.79.0`

那么：
1. 网关大概率是 `192.168.79.2`
2. 你的三台虚拟机就应使用同网段静态 IP

## 5.1.1 登录后先确认网卡名和当前网关

不要直接假设你的网卡一定叫 `ens33`，先在每台机器里执行：

```bash
ip addr
ip route
```

你要观察两件事：

1. 哪个网卡拿到了 IP
   - 常见名称：`ens33`、`ens160`
2. 默认网关是多少
   - `default via ...` 后面的地址就是网关

如果你的网卡不是 `ens33`，下面的 netplan 配置里要把 `ens33` 改成你自己的实际网卡名。

## 5.2 启动第一台虚拟机

### 操作步骤
1. 选中 `k8s-master`
2. 点击 `Power on this virtual machine`
3. 等待系统启动
4. 登录系统

### 账号密码怎么办
当前老师提供的 PDF 中没有写账号密码。如果登录界面你不知道密码：
1. 先看看老师课堂群或单独说明
2. 若仍没有，请直接问老师要虚拟机默认账号密码

不要在这里卡太久。

## 5.3 配置静态 IP

老师给的配置思路是这样的：

| 节点 | IP |
|---|---|
| `k8s-master` | `192.168.79.133` |
| `k8s-worker1` | `192.168.79.134` |
| `k8s-worker2` | `192.168.79.135` |

请把 `192.168.79` 改成你自己 VMware NAT 的实际网段。

### 在每台虚拟机中执行
先打开终端。

```bash
sudo vim /etc/netplan/00-installer-config.yaml
```

将内容改为下面格式：

```yaml
network:
  ethernets:
    ens33:
      addresses:
        - 192.168.79.133/24
      routes:
        - to: default
          via: 192.168.79.2
      nameservers:
        addresses: [114.114.114.114, 8.8.8.8]
      dhcp4: false
      dhcp6: false
  version: 2
```

注意两点：
1. 如果你上一步看到的实际网卡名不是 `ens33`，这里必须改成真实名称
2. `via: 192.168.79.2` 也必须改成你 `ip route` 看到的真实默认网关

### 三台机器分别改成
1. Master：`192.168.79.133/24`
2. Worker1：`192.168.79.134/24`
3. Worker2：`192.168.79.135/24`

保存后执行：

```bash
sudo netplan apply
ip addr
```

如果能看到新 IP，说明生效了。

## 5.4 设置主机名

### Master 执行

```bash
sudo hostnamectl set-hostname k8s-master
```

### Worker1 执行

```bash
sudo hostnamectl set-hostname k8s-worker1
```

### Worker2 执行

```bash
sudo hostnamectl set-hostname k8s-worker2
```

执行后可用下面命令确认：

```bash
hostname
```

## 5.5 配置 `/etc/hosts`

三台机器都要执行：

```bash
sudo tee -a /etc/hosts > /dev/null <<EOF
192.168.79.133 k8s-master
192.168.79.134 k8s-worker1
192.168.79.135 k8s-worker2
EOF
```

注意：
如果你的网段不是 `192.168.79`，这里也要一起改。
2. 这里使用 `sudo tee`，是因为普通用户直接 `>> /etc/hosts` 往往会遇到权限错误。

## 5.6 节点互通测试

三台机器上分别执行：

```bash
ping k8s-master
ping k8s-worker1
ping k8s-worker2
```

能互通后，再进入下一步。

## 6. 第一周 Day2：初始化 Kubernetes 集群

## 6.0 初始化前先做健康检查

在 Master 和两个 Worker 上都先执行：

```bash
free -h
swapon --show
systemctl status containerd --no-pager
systemctl status kubelet --no-pager
```

你要确认：

1. `containerd` 是 active
2. `kubelet` 是 active 或至少能正常启动
3. 如果 `swapon --show` 有输出，说明交换分区还开着，先执行：

```bash
sudo swapoff -a
```

如果你想彻底关闭开机自动挂载交换分区，再执行：

```bash
sudo sed -i.bak '/ swap / s/^/#/' /etc/fstab
```

## 6.0.1 如果之前初始化失败过

先在失败节点执行：

```bash
sudo kubeadm reset -f
sudo rm -rf /etc/cni/net.d
sudo systemctl restart containerd
sudo systemctl restart kubelet
```

再重新执行初始化或 join，避免旧配置残留。

## 6.1 在 Master 上执行初始化

老师 PDF 给出的命令如下，你只需要改 IP：

```bash
sudo kubeadm init \
  --apiserver-advertise-address=192.168.79.133 \
  --image-repository=registry.aliyuncs.com/google_containers \
  --kubernetes-version=v1.28.2 \
  --service-cidr=10.96.0.0/12 \
  --pod-network-cidr=10.244.0.0/16 \
  --ignore-preflight-errors=all
```

关于 `--ignore-preflight-errors=all`：

1. 这是老师给的命令，目的是减少环境细节导致的报错中断
2. 但它不代表前置问题不存在，所以你一定要先完成上面的健康检查
3. 如果初始化后节点状态异常，不要硬扛，优先回到 `6.0` 重新检查

执行成功后，终端会输出一段 `kubeadm join ...` 命令。

### 你要做两件事
1. 把这段 `join` 命令复制保存下来
2. 后面到两个 Worker 上执行

## 6.2 配置 kubectl

在 Master 上继续执行：

```bash
mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

## 6.3 安装网络插件

如果老师虚拟机已经准备了镜像，一般 Calico 会比较顺利：

先下载配置文件：

```bash
curl -O https://raw.githubusercontent.com/projectcalico/calico/v3.26.1/manifests/calico.yaml
```

因为你前面的 `kubeadm init` 使用的是 `--pod-network-cidr=10.244.0.0/16`，所以这里要把 Calico 默认网段改成同一个值。

打开文件：

```bash
vim calico.yaml
```

搜索 `CALICO_IPV4POOL_CIDR`，把它附近的值改成：

```yaml
- name: CALICO_IPV4POOL_CIDR
  value: "10.244.0.0/16"
```

再执行：

```bash
kubectl apply -f calico.yaml
```

这样就能保证：
1. `kubeadm init` 的 Pod 网段
2. Calico 使用的网段

二者保持一致，避免新手最容易踩的网络插件网段不一致问题。

## 6.4 让 Worker 加入集群

在 `k8s-worker1` 和 `k8s-worker2` 上分别执行 Master 初始化时得到的 `kubeadm join ...` 命令。

## 6.5 检查集群状态

回到 Master 执行：

```bash
kubectl get nodes
kubectl get pods -A
```

如果看到 3 个节点状态逐步变成 `Ready`，说明集群成功。

## 13. 第二周 Day4：配置 Jenkins 与 GitOps

## 13.1 Jenkins 负责什么

1. 拉取 Git 代码
2. 执行 `mvn clean package`
3. 执行前端打包
4. 构建镜像
5. 更新部署仓库中的 YAML

## 13.2 Argo CD 负责什么

1. 监听 Git 中的 K8s YAML
2. 自动同步到集群
3. 实现 GitOps 式部署

## 13.3 你答辩时可以这样讲

“开发代码提交到 Git 后，Jenkins 负责持续集成，Argo CD 负责持续部署，Kubernetes 完成运行承载，Prometheus 负责运行监控。”

这句话非常适合答辩总结。

## 15. 你现在立刻该做什么

如果按最稳的顺序推进，你现在就做下面 5 件事：

1. 在 Windows 安装 VMware Workstation
2. 用 `.vmx` 文件导入老师提供的虚拟机
3. 复制成 3 台虚拟机
4. 按本文配置静态 IP、主机名和 hosts
5. 完成 `kubeadm init` 和 `join`

只有这一步完成了，后面 K8s 部署才真正有基础。
